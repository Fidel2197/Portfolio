My approach

How I build.

I start with a small working version, test it, and improve it as I find problems.

Start with the main task

I sketch the main flow first: upload a CSV and download a report, or take a food photo and save a recipe. That helps me decide which screens and features to build.

Work out what gets saved

I decide where data belongs before adding save controls. DataDock uses PostgreSQL for account reports. SignalDesk saves practice progress in the browser.

Test the awkward cases

I check invalid files, failed requests, sign-out, and refresh behavior. Automated tests cover those cases, and I check the deployed app as well.

Use feedback

A clipped sidebar in DataDock and disappearing status changes in SignalDesk both led to fixes. I try to reproduce a reported problem before changing the code.

Development tools

I use AI-assisted tools for implementation, refactoring, documentation, and testing. I choose the requirements, review the code and behavior, and test the result.
