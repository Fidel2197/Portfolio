My approach

Build, inspect, improve.

I start with what someone needs to do, then refine the application using feedback about its behavior and presentation.

Start with a concrete workflow

DataDock follows upload, inspect, clean, and export. SnapChef connects a food photo to recipe ideas and saved results. SignalDesk separates incident practice from public service checks.

Make the data boundary clear

A saved browser setting is different from an account-backed record. Build notes explain where information goes, what persists, and which features use example data or external services.

Use feedback to find the next change

DataDock’s clipped sidebar prompted a layout fix. SignalDesk’s lost status changes prompted browser persistence. This portfolio’s repeated sections prompted a shorter homepage and individual project pages.

AI-assisted development

I set project goals and request revisions to the product and interface. Codex assists with implementation, refactoring, documentation, and checks. The repositories expose the resulting code, tests, and limitations for review. The bookstore is a collaborative team project and is identified separately.

Keep verification visible

Build notes and repository instructions describe what can fail and how to run the available checks. Automated tests are evidence for the behavior they cover; they do not make external APIs, account providers, or every device configuration failure-proof.
